# Router status monitoring

Личный тестовый монитор TP-Link Archer A6 и AX23 через GitHub Actions + Firebase Cloud Messaging. Без VPS и без Firebase Cloud Functions. GitHub расписание: каждые 10 минут на 7/17/27/37/47/57 минуте часа. Плановые запуски могут задерживаться; точного срока доставки push нет.

## Что делает

- Читает список устройств из облака TP-Link по уже подтверждённой сессии Tether.
- Отправляет push «не в сети» и «снова в сети» с моделью и привязанным адресом при изменении состояния.
- При первом включении offline тоже уведомляет; исходный online не уведомляет.
- Пропавшая запись, неизвестный статус, сбой API и истёкший токен не выдаются за выключенный роутер.
- Ошибки мониторинга дают отдельное уведомление один раз до изменения состояния ошибки.
- Состояние между запусками — зашифрованный Fernet файл в GitHub Actions artifact, срок хранения 2 дня. В публичном репозитории нет токенов, адресов и открытого состояния устройств.
- Пользовательское уведомление FCM доставляется средствами Android, даже когда приложение не открыто. Нужны интернет и разрешение уведомлений. После принудительной остановки приложения через системные настройки его нужно снова открыть. Гарантировать мгновенную доставку или доставку на отключённый телефон нельзя.

## Настройка

В Settings → Secrets and variables → Actions добавьте Repository secrets:

1. `MONITOR_CONFIG_JSON` — содержимое файла, экспортированного из Android-приложения 0.6: «Роутеры» → «Экспорт для мониторинга GitHub». До экспорта войдите в TP-Link и привяжите роутеры к адресам. Файл включает токен облака и FCM-токен телефона; пароля нет. Не добавляйте его как файл репозитория.
2. `FCM_SERVICE_ACCOUNT_JSON` — JSON ключ сервисного аккаунта Firebase того же проекта, что приложение. Аккаунту нужно разрешение отправки FCM, минимально роль `roles/firebasecloudmessaging.admin`. Не публикуйте ключ. Для личного теста допустим ключ; для постоянного использования лучше перейти на GitHub OIDC → Google Workload Identity Federation без долгоживущего ключа.
3. `STATE_KEY` — один постоянный Fernet-ключ. Создать локально: `python3 -c 'import os,base64; print(base64.urlsafe_b64encode(os.urandom(32)).decode())'`. Поместите результат в Secret, не в код. Не меняйте его без необходимости: прежнее состояние не расшифруется.

Без секретов workflow выводит «Monitoring is not active» и не опрашивает аккаунт. Зелёный запуск до настройки НЕ означает, что мониторинг активен.

Actions → Router monitoring → Run workflow → включите `test_push`. После настройки должен прийти тестовый push. Затем проверьте offline/online реального роутера при закрытом приложении. До такого теста нельзя считать доставку подтверждённой.

Если приложение переустановлено, обновился FCM-токен, изменились адреса/привязки или завершилась TP-Link сессия, повторите экспорт и замените MONITOR_CONFIG_JSON. Пароль облака сервер не хранит, автоматического продления сессии нет.

## Состояние и ограничения

Артефакт зашифрован, в лог выводятся только тип ошибки, число уведомлений и общий health. При сбое чтения/расшифровки состояния монитор останавливается безопасно, не выдумывая переходов. Если отправка FCM не удалась, новое состояние не сохраняется: на следующем запуске выполняется повторная попытка. Если сбой произошёл после успешной доставки части уведомлений, возможна повторная доставка; Android notification tag уменьшает дубли в панели, но это не гарантия exactly-once.

Если все прежние артефакты удалены/истекли, начинается новая базовая проверка. Первое offline может уведомить повторно. Максимальное параллельное выполнение — одно, чтобы проверки не конкурировали за состояние. В публичном репозитории GitHub может отключить cron после длительного отсутствия активности; проверяйте Actions, особенно после длительного перерыва.

Состояние главной/виджета Android пока обновляется из собственных запросов приложения. Push сообщает изменение отдельно; работающий Actions не означает автоматическую синхронизацию всех карточек на телефоне. Наличие связи с облаком не измеряет питание электросети.

Протокол сопоставлен с Tether 4.16.27; запросы подписаны, TLS проверяется с корнями из официального Tether. Поддержка API сторонняя и может измениться.

## Тесты

`python3 -m unittest -v` — переходы, отсутствие ложного offline, сбои облака, пагинация и проверка адресов серверов. Работают без секретов и внешних запросов.

## Бесплатное использование

Стандартные GitHub-hosted runners для публичных репозиториев бесплатны в рамках правил GitHub; хранение артефактов ограничено тарифом. Код должен оставаться публичным, а все секреты — в Actions Secrets. FCM не требует развёртывания платных Cloud Functions.
